# 352 Air Purifier for Home Assistant

为 352 品牌空气净化器打造的 Home Assistant 局域网集成。

**脱离云端，完全本地 UDP 控制。**

> **本仓库是 fork，基于 [`yymonday/ha-352-airpurifier`](https://github.com/yymonday/ha-352-airpurifier)。**
> 原始协议逆向、X83/X50 的 `A5 A0` 实现均来自原作者 **[@yymonday](https://github.com/yymonday)**，
> 在此表示感谢。
>
> 本 fork（**[@freddy-yu](https://github.com/freddy-yu)**）的改动：
>
> 1. **新增 `F0 72` 协议层**（`protocol.py`）：CRC16、新帧构造/解析、状态字段映射。
> 2. **重写通信层**：按型号双协议发送、认证码自动学习、设备上报即真相。
> 3. **修复原实现的三个问题**：
>    - 命令后 3 秒锁状态会永久丢弃设备真实的关机/调速回帧
>    - 只发广播发现设备，而 X50S 不回应广播（改为广播+单播双发）
>    - 手动模式用错取值（`0x05` → `0x04`）
> 4. **X50S 真机验证**：开关机、风速 1–5、模式、灯光、童锁全部实测通过。
> 5. **包名从 `air_352_x83` 改为 `air_352`** —— 原名字带型号后缀，容易误导（本集成支持多型号）。
> 6. 新增离线测试套件（`tests/`）和只读局域网诊断脚本。
> 7. 补充 `F0FE6B*` 的 DHCP 自动发现前缀（实测 X50S 的 MAC 前缀）。
> 8. **新增 `select` 实体选运行模式** —— HA 风扇卡片默认不显示模式下拉框，
>    单靠 `preset_mode` 容易让人误以为不支持模式。
> 9. **新增 `select` 实体选风速档位** —— 同理，卡片默认不显示风速滑块。
>
> 变更细节见 [`docs/X50S-协议逆向笔记.md`](docs/X50S-协议逆向笔记.md) 第 12 节「实机验证记录」。

## 支持的型号

| 型号 | 协议 | 验证状态 |
|---|---|---|
| 352 X50S | `F0 72` 帧 | **已真机验证** |
| 352 X50（老固件） | `A5 A0` 帧 | 沿用原实现，未实测 |
| 352 X83 / X83C | `A5 A0` 帧 | 沿用原实现，未实测 |
| 352 X60 / X70 / G30 | `F0 72` 帧 | 按同族实现，未实测 |

X50 与 X50S 在协议层是同一个设备类型（`0x03`），区别在内层帧格式：
老固件用 `A5 A0` + 单字节累加和，新固件用 `F0 72` + CRC16。
**如果你选 X50 控制没反应，请改选 X50S。**

## X50S 实测结论（2026-10）

在一台 X50S 上逐条验证的结果：

- ✅ 开关机、风速 1–5 档、模式（自动/睡眠/极速/手动）、灯光、童锁 全部生效
- ✅ 认证码自动学习有效（该机 `auth=0x1D05`、`company=0xF2`）
- ⚠️ **设备不回应 IPv4 广播，只回应单播** —— 集成已改为广播+单播双发
- ⚠️ **定时命令 `0x54` 无响应** —— X50S 不支持，集成会直接拒绝而非发无效帧
- ⚠️ **无温湿度/CO₂ 传感器** —— 这些字段上报恒为 0，故 X50S 不创建对应实体
- ℹ️ 手动模式对应 `raw=4`（App 常量表写的是 5，那是老固件）
- ℹ️ 极速模式下设备会跑到 6 档，超出 5 档范围属正常

## 核心特性

- ⚡ **完全本地化**：不依赖 352 官方云服务，断网依然可用
- 🔄 **状态即时同步**：UDP 直连，设备状态变化会主动推送
- 🌀 **风机控制**：开关机、1–5 档无极调速（X50S）
- 🎛️ **模式切换**：自动 / 睡眠 / 极速 / 手动
- 💡 **灯光控制**：屏幕灯开关
- 🔒 **童锁**：远程上锁/解锁（已实测）
- 📊 **传感器**：PM2.5、累计净化量、滤芯状态

## 安装

### HACS（推荐）

1. 打开 Home Assistant，进入 HACS
2. 右上角 `...` → **自定义存储库 (Custom repositories)**
3. 仓库 URL 填 `https://github.com/freddy-yu/ha-352-airpurifier`，类别选 **集成 (Integration)**
4. 在 HACS 中搜索 `352 Air Purifier` 并下载安装
5. 重启 Home Assistant

### 手动安装

把 `custom_components/air_352` 整个文件夹复制到你的 HA 配置目录下的
`custom_components/` 中，然后重启。

> **从旧版本升级（包名变更）**
>
> 本 fork 早期版本和上游都叫 `custom_components/air_352_x83`。
> 如果你装过那些版本，升级时需要：
>
> 1. 删除 HA 配置里的旧集成条目
> 2. 删除 `custom_components/air_352_x83` 目录（否则会两个集成共存）
> 3. 放入新的 `custom_components/air_352`，重启 HA
> 4. 重新添加集成（实体 unique_id 不变，但设备卡会重建）
>
> 不删旧目录会导致 domain 冲突，HA 启动时可能报错。

## 配置

1. **设置** → **设备与服务** → 右下角 **添加集成**，搜索 `352`
2. 填写：

   - **型号**：选择对应型号（X50S 请选 `352 X50S 空气净化器`）
   - **IP 地址**：净化器的局域网 IP（建议在路由器上绑定静态 IP）
   - **MAC 地址**：设备 MAC，格式 `00:95:69:D7:9B:FE`
   - **认证码**（可选）：形如 `22B5` 的十六进制值

3. 提交后会自动生成风扇、灯光和多个传感器实体

### 关于认证码

设备的认证码由厂商云端下发，每台不同。本集成会**自动学习**：
首次广播搜索后，从设备回帧的包头里提取真实认证码并记住。

只有在自动学习失败（比如设备不回应搜索）时，才需要手动填。
手动填写后集成不再覆盖该值。

### 关于端口

集成会尝试监听 UDP `11530`。如果该端口被 352 官方 App 占用，
会自动改用临时端口——此时设备应答仍能收到，但设备主动广播可能收不到，
建议在手机上关闭 352 App 后重启集成。

## 实体

- `fan`：主控（开关、风速、预设模式）
- `select.运行模式`：**自动 / 睡眠 / 极速 / 手动**
- `select.风速档位`：**1–5 档**（手动模式下用它调档）
- `light`：屏幕灯（**仅设备开机时可用**，见下）
- `sensor.pm25`、`sensor.speed`、`sensor.cumulative_purification`、`sensor.filter_type`
- X50S 实测没有温湿度/CO₂ 传感器，因此不创建这些实体
- `sensor.total_purification` 为诊断实体（X50S 上恒为 0）

### 关于风速档位（重要）

`sensor.speed` 和 `select.风速档位` 显示的是**设备当前实际风速**，不是「设定值」。
实测 X50S 的行为：

- **自动模式**：档位由设备根据空气质量自己调，空气好时常年停在 1 档
- **睡眠模式**：固定最低档（1 档）
- **极速模式**：设备跑到 **6 档**（超出常规 1–5 档，此时 `select` 显示未知，属正常）
- **手动模式**：才是你选的档位，1–5 都能精确生效

所以「不管什么模式档位都是 1」不是 bug：
如果你在自动或睡眠模式，设备本来就只跑 1 档。
**要手动调速：先选「手动」模式，再用「风速档位」调。**

> 设备没有区分「设定档位」和「实际档位」，只上报一个值，
> 所以自动模式下调档位会被设备的自动策略覆盖——这是设备设计。

### 为什么另外提供 select 实体？

`fan` 实体本身支持 `preset_mode` 和 `percentage`，这是标准做法。
但 Home Assistant 的**风扇卡片（tile card）默认既不渲染模式下拉框，
也不渲染风速滑块**，需要在卡片上手动添加功能才看得到，
很容易让人误以为不支持。

所以额外提供 `运行模式` 和 `风速档位` 两个 `select` 实体：
任何卡片、自动化、语音助手都能直接选用。三个入口共享同一状态。

> 如果你更想用风扇卡片：编辑卡片 → 添加功能 →
> 选「Preset modes」（预设模式）和「Speed」（风速）即可。

### 关机状态下的行为

实测 X50S：

- **关机时灯光命令被忽略**，设备无任何响应
- 关机会把灯光状态重置为「开」，此时上报的 `light` 值无参考意义
- **模式 / 风速命令同样会被忽略，但集成会自动先开机再发**

所以：

- `light` 在设备关机时显示为**不可用**，请先开风扇再调灯
- 在关机状态调模式或风速，集成会**先发开机命令，等 0.8 秒让设备初始化完成**，
  再发目标命令（否则紧跟的命令会被开机初始化流程覆盖）

## 协议

协议细节（帧结构、CRC 算法、状态字段偏移、命令码表）见
[`docs/X50S-协议逆向笔记.md`](docs/X50S-协议逆向笔记.md)。

实现代码在 `custom_components/air_352/protocol.py`，纯 Python 无 HA 依赖，
可以直接用 `tests/` 下的脚本离线验证：

```bash
python tests/test_protocol.py   # 帧构造/CRC/解析
python tests/test_hub.py        # 认证码学习/状态合并
python tests/test_entity.py     # fan/light 实体层命令序列
python tests/test_select.py     # 模式/档位 select 实体 + hub 接口
python tests/test_sensor.py     # sensor 实体取值
```

真机验证（需要设备在网）：

```bash
python tests/probe_device.py 192.168.0.29   # 只读诊断
python tests/probe_verify.py                # 逐条命令查询确认
python tests/test_live_entity.py            # 实体层端到端
python tests/test_live_select.py            # 模式/档位选择端到端
```

## 已知限制

- 定时开关机组（`0x0B` / `0x54`）、PTC 在 X50S 上无响应，未做成实体
- 关机时无法单独控制灯光（设备限制，非集成问题）
- X60 / X70 / G30 按同族协议实现，未经真机验证
- 滤芯写入（SN 码）未实现
