## 正文

之前 aexyun 发的 [352空气净化器局域网接入插件-X83](https://bbs.hassbian.com/forum.php?mod=viewthread&tid=32155)
很好用，但只完美支持 X83。我手上是 **X50S**，拿原插件去控制完全没反应，只读取得到状态。

花时间把 352 官方 App 逆向了一遍，发现原因是**固件换了新的帧格式**：

- X83 / 老 X50 用的是 `A5 A0` 老帧，单字节累加和
- **X50S 用的是 `F0 72` 新帧，带 CRC16**

两套协议不兼容，所以原插件对 X50S 只能读到状态、发不出有效控制命令。

现在 X50S 已经完整支持，功能全部在真机上逐项验证过。

### 支持的功能

- 开关机
- 四种运行模式：自动 / 睡眠 / 极速 / 手动
- 风速 1–5 档
- 屏幕灯开关
- 童锁开关
- 传感器：PM2.5、当前风速、累计净化量、滤芯状态
- 状态变化主动推送，不用轮询

### 安装

**HACS 安装（推荐）**

1. HACS → 右上角 `...` → 自定义存储库
2. 添加 `https://github.com/freddy-yu/ha-352-x50s-airpurifier`
3. 类别选「集成」
4. 搜索 `352 X50S` 安装
5. 重启 Home Assistant

**手动安装**

把 `custom_components/air_352_x50s` 复制到 HA 配置目录的 `custom_components/` 下，重启。

### 配置

设置 → 设备与服务 → 添加集成 → 搜索 `352`：

- **型号**：选 `352 X50S 空气净化器`
- **IP 地址**：设备的局域网 IP（建议在路由器绑定静态 IP）
- **MAC 地址**：格式如 `F0:FE:6B:93:88:FF`
- **认证码**：可以留空，插件会自动从设备回帧里学习

### 使用上的两点说明

**1. 模式/档位用 select 实体**

HA 的风扇卡片默认不显示模式下拉框和风速滑块，很多人会以为插件不支持。
所以额外提供了两个 `select` 实体：

- `select.运行模式` —— 自动 / 睡眠 / 极速 / 手动
- `select.风速档位` —— 1–5 档

也可以编辑风扇卡片 → 添加功能 → 勾选「Preset modes」和「Speed」。

**2. 不同模式下档位表现不同**

设备只上报「当前风速」，不区分设定值和实际值：

- **自动模式**：设备按空气质量自己调，空气好时长期停在 1 档
- **睡眠模式**：固定 1 档
- **极速模式**：跑到 6 档（超出可选范围，此时档位实体显示未知）
- **手动模式**：你选几档就是几档

想让风速保持你设定的值，请用**手动模式**。这不是 bug，
是因为在自动模式下，设备自己接管了风速控制。

### 已知限制

- **只实测了 X50S**。X83 / X50 / X60 / X70 / G30 沿用了原作者的实现或按同族协议推断，**没在真机上验证过**
- X50S 不支持定时开关机和 PTC，命令发下去设备无响应，所以没做
- 滤芯 SN 写入没实现
- 关机状态下灯光命令会被忽略，所以灯实体会显示不可用。模式和档位命令会自动先开机再执行

### 和原帖版本的关系

原始项目和 X83/X50 的支持来自 [@yymonday](https://github.com/yymonday) 和发帖的 aexyun，
协议逆向成果归他们。我这个是 fork，主要补了 X50S 的新协议和几个状态处理的修复：

- 新增 `F0 72` 协议层（CRC16、新帧构造/解析、状态字段映射）
- 双协议按型号自动选择
- 认证码自动学习，不用手填
- 修复：原实现在命令后锁 3 秒状态，会永久丢弃设备真实的关机/调速回帧
- 修复：X50S 不回应 IPv4 广播，改为广播 + 单播双发（否则一直显示离线）
- 修复：手动模式取值应为 `0x04`，`0x05` 在 X50S 上无响应
